# 权限控制核心机制详解：如何控制"只能查看自己参与项目的进度"

## 核心原理

权限控制通过 **SQL 子查询 + project_members 表** 实现，在数据库层面过滤数据。

---

## 一、核心数据表：project_members

### 1.1 表结构

```sql
CREATE TABLE `project_members` (
  `id` varchar(32) NOT NULL COMMENT '成员ID',
  `project_id` varchar(32) COMMENT '项目ID（逻辑关联）',
  `user_id` varchar(32) COMMENT '用户ID（逻辑关联）',
  `role` varchar(50) NOT NULL COMMENT '项目角色',
  `is_active` tinyint(1) NOT NULL DEFAULT '1' COMMENT '是否启用（0:已移除，1:在职）',
  `created_at` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP,
  `updated_at` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  KEY `idx_project_id` (`project_id`),
  KEY `idx_user_id` (`user_id`),
  KEY `idx_is_active` (`is_active`)
) COMMENT='项目成员表';
```

### 1.2 关键字段说明

| 字段 | 类型 | 说明 | 作用 |
|-----|------|------|------|
| `project_id` | varchar(32) | 项目 ID | 关联到 projects 表 |
| `user_id` | varchar(32) | 用户 ID | 关联到 sys_user 表 |
| `is_active` | tinyint(1) | 是否在职 | 1=在职，0=已移除 |
| `role` | varchar(50) | 项目角色 | 如：项目经理、设计师、施工员等 |

### 1.3 示例数据

```sql
-- 项目 2744637c 的成员列表
INSERT INTO project_members (id, project_id, user_id, role, is_active) VALUES
('xxx1', '2744637c89224c718f509e6d60385187', '2',   'SJZJ', 1),  -- 用户2: 设计总监
('xxx2', '2744637c89224c718f509e6d60385187', '103', 'GCJL', 1),  -- 用户103: 工程经理
('xxx3', '2744637c89224c718f509e6d60385187', '104', 'XMZJ', 1),  -- 用户104: 项目总监
```

**含义**：
- 用户 2、103、104、105 都是项目 `2744637c` 的成员
- 只有这些用户能查看该项目的进度数据

## 二、权限控制的 SQL 实现

### 2.1 完整的查询 SQL

```xml
<select id="selectProjectSchedulesList" parameterType="ProjectSchedules" resultMap="ProjectSchedulesResult">
    SELECT
        ps.id, ps.project_id, ps.stage, ps.status, ps.completion_rate, ...
    FROM project_schedules ps
    WHERE
        <!-- 🔑 核心权限控制逻辑 -->
        <if test="isAdmin != null and isAdmin == true">
            <!-- 管理员：查看所有项目的进度 -->
            1=1
        </if>
        <if test="isAdmin == null or isAdmin == false">
            <!-- 普通员工：只能查看参与项目的进度 -->
            <if test="currentUserId != null and currentUserId != ''">
                AND ps.project_id IN (
                    SELECT pm.project_id
                    FROM project_members pm
                    WHERE pm.user_id = #{currentUserId} 
                      AND pm.is_active = 1
                )
            </if>
        </if>
        <!-- 其他查询条件 -->
        AND ps.status = 'IN_PROGRESS'
    ORDER BY ps.stage_order ASC
</select>
```

### 2.2 SQL 子查询详解

#### 关键部分：

```sql
AND ps.project_id IN (
    SELECT pm.project_id
    FROM project_members pm
    WHERE pm.user_id = #{currentUserId} 
      AND pm.is_active = 1
)
```

**执行逻辑**：

1. **子查询**：从 `project_members` 表中查询当前用户参与的所有项目 ID
   ```sql
   SELECT pm.project_id
   FROM project_members pm
   WHERE pm.user_id = '103'  -- 假设当前用户 ID 是 103
     AND pm.is_active = 1     -- 只查询在职成员
   ```
   
   **结果示例**：
   ```
   project_id
   ----------
   2744637c89224c718f509e6d60385187
   abc123def456789
   xyz789abc123456
   ```

2. **主查询**：只查询这些项目的进度数据
   ```sql
   SELECT ps.*
   FROM project_schedules ps
   WHERE ps.project_id IN ('2744637c...', 'abc123...', 'xyz789...')
   ```

## 五、关键代码位置

### 5.1 Service 层注入用户信息

**文件**: `ProjectSchedulesServiceImpl.java`

```java
@Override
public List<ProjectSchedules> selectProjectSchedulesList(ProjectSchedules projectSchedules) {
    // 🔑 关键步骤1：获取当前用户ID
    Long currentUserId = SecurityUtils.getUserId();
    
    if (currentUserId != null) {
        // 🔑 关键步骤2：注入用户ID到查询对象
        projectSchedules.setCurrentUserId(String.valueOf(currentUserId));
        
        // 🔑 关键步骤3：判断是否为管理员
        projectSchedules.setIsAdmin(SecurityUtils.isAdmin(currentUserId));
    }
    
    // 🔑 关键步骤4：执行带权限过滤的查询
    return projectSchedulesMapper.selectProjectSchedulesList(projectSchedules);
}
```

## 六、总结

### 6.1 权限控制的核心

**"只能查看自己参与项目的进度"** 是通过以下机制实现的：

1. **project_members 表**：存储用户与项目的关联关系
2. **SQL 子查询**：在数据库层面过滤数据
3. **is_active 字段**：确保只查询在职成员的项目

### 6.2 控制点总结

| 层级 | 控制点 | 作用 |
|-----|--------|------|
| **Controller** | `@PreAuthorize` | 验证接口访问权限 |
| **Service** | `setCurrentUserId()` + `setIsAdmin()` | 注入用户身份信息 |
| **Mapper** | SQL 子查询 `IN (SELECT ...)` | 数据库层面过滤数据 |
| **数据表** | `project_members` | 存储用户-项目关联关系 |

### 6.3 优势

✅ **数据库层面过滤**：性能高效，无法绕过  
✅ **自动化**：Service 层自动注入权限信息  
✅ **灵活性**：通过 `is_active` 字段控制成员状态  
✅ **可扩展**：可以基于 `role` 字段实现更细粒度的权限控制

### 6.4 关键 SQL

```sql
-- 这就是控制"只能查看自己参与项目"的核心 SQL
AND ps.project_id IN (
    SELECT pm.project_id
    FROM project_members pm
    WHERE pm.user_id = #{currentUserId} 
      AND pm.is_active = 1
)
```

这个子查询确保了：
- 只查询当前用户作为成员参与的项目
- 只查询在职成员（is_active = 1）的项目
- 在数据库层面实现数据隔离
