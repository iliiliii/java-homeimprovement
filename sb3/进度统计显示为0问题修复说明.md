# 进度统计显示为 0 问题修复说明

## 问题描述

在 `vue3/src/views/evs/projectScheduleRecords/card.vue` 页面中，项目卡片的进度统计信息一直显示为 0：

```vue
<div class="progress-summary">
  已完成 {{ project.completedSchedules || 0 }}/{{ project.totalSchedules || 0 }} 
  · 进行中 {{ project.inProgressSchedules || 0 }}
</div>
```

**显示效果**：已完成 0/0 · 进行中 0

**预期效果**：已完成 3/8 · 进行中 2

---

## 问题原因

### 1. 前端 API 调用错误

**问题代码**（修复前）：
```javascript
// vue3/src/api/evs/projects.js
export function listProjectsWithMembers(query) {
  return request({
    url: '/evs/projects/list',
    method: 'get',
    params: {
      ...query,
      includeProjectMembers: true  // ❌ 只请求成员信息，没有进度统计
    }
  })
}
```

### 2. 后端接口逻辑

后端 `ProjectsController.list()` 方法的处理逻辑：

```java
if ("true".equals(includeScheduleInfo)) {
    // 进度统计查询（带权限控制）
    list = projectsService.selectProjectsListWithScheduleInfo(projects);
} else if (includeRelations.length() > 0) {
    // 有关联查询参数，使用 selectProjectsWithRelations
    list = projectsService.selectProjectsWithRelations(...);
} else {
    // 普通列表查询（带权限控制）
    list = projectsService.selectProjectsList(projects);
}
```

**问题分析**：
- 前端传了 `includeProjectMembers=true`，走的是第二个分支 `selectProjectsWithRelations`
- 这个方法只返回项目基本信息和成员信息，**不包含进度统计字段**
- 进度统计字段（`completedSchedules`、`totalSchedules`、`inProgressSchedules`、`progressRate`）都是 `null`
- 前端使用 `|| 0` 兜底，所以显示为 0

---

## 修复方案

### 修改前端 API 调用

**修复后的代码**：
```javascript
// vue3/src/api/evs/projects.js
export function listProjectsWithMembers(query) {
  return request({
    url: '/evs/projects/list',
    method: 'get',
    params: {
      ...query,
      includeScheduleInfo: true  // ✅ 获取进度统计信息（已包含权限过滤）
    }
  })
}
```

**修改说明**：
- 将 `includeProjectMembers: true` 改为 `includeScheduleInfo: true`
- `selectProjectsListWithScheduleInfo` 方法已经包含了权限过滤逻辑
- 该方法会返回项目列表 + 进度统计信息

---

## 后端实现分析

### selectProjectsListWithScheduleInfo 方法

**文件**：`ProjectsServiceImpl.java`

```java
@Override
public List<Projects> selectProjectsListWithScheduleInfo(Projects projects) {
    // 1. 设置权限信息（自动应用权限控制）
    Projects query = setCurrentUser(projects);
    
    // 2. 查询项目列表（带权限过滤）
    List<Projects> projectsList = projectsMapper.selectProjectsList(query);
    
    // 3. 如果无项目，直接返回
    if (projectsList.isEmpty()) {
        return projectsList;
    }
    
    // 4. 获取所有项目ID
    List<String> projectIds = projectsList.stream()
            .map(Projects::getId)
            .collect(Collectors.toList());
    
    // 5. 批量查询进度统计
    Map<String, Map<String, Object>> statsMap = projectsMapper.selectScheduleStatsMap(projectIds);
    
    // 6. 为每个项目设置统计信息
    for (Projects project : projectsList) {
        Map<String, Object> stats = statsMap.get(project.getId());
        if (stats != null) {
            project.setTotalSchedules(((Number) stats.get("total_count")).longValue());
            project.setCompletedSchedules(((Number) stats.get("completed_count")).longValue());
            project.setInProgressSchedules(((Number) stats.get("in_progress_count")).longValue());
            project.setProgressRate(((Number) stats.get("progress_rate")).intValue());
        } else {
            // 如果没有进度数据，初始化为0
            project.setTotalSchedules(0L);
            project.setCompletedSchedules(0L);
            project.setInProgressSchedules(0L);
            project.setProgressRate(0);
        }
    }
    
    return projectsList;
}
```

**关键点**：
1. ✅ 包含权限过滤（通过 `setCurrentUser` 方法）
2. ✅ 批量查询进度统计（性能优化）
3. ✅ 自动计算完成率

---

### selectScheduleStatsMap SQL

**文件**：`ProjectsMapper.xml`

```xml
<select id="selectScheduleStatsMap" parameterType="java.util.List" resultType="java.util.Map">
    SELECT
        project_id,
        COUNT(*) as total_count,
        SUM(CASE WHEN status = 'COMPLETED' THEN 1 ELSE 0 END) as completed_count,
        SUM(CASE WHEN status = 'IN_PROGRESS' THEN 1 ELSE 0 END) as in_progress_count,
        ROUND(CASE
            WHEN COUNT(*) > 0 THEN
                SUM(CASE WHEN status = 'COMPLETED' THEN 1 ELSE 0 END) * 100.0 / COUNT(*)
            ELSE 0
        END, 0) as progress_rate
    FROM project_schedules
    WHERE project_id IN
    <foreach collection="projectIds" item="id" open="(" separator="," close=")">
        #{id}
    </foreach>
    GROUP BY project_id
</select>
```

**统计逻辑**：
- `total_count`：项目的总进度数
- `completed_count`：状态为 'COMPLETED' 的进度数
- `in_progress_count`：状态为 'IN_PROGRESS' 的进度数
- `progress_rate`：完成率 = (已完成数 / 总数) × 100

## 权限控制说明

### 为什么不需要 includeProjectMembers？

`selectProjectsListWithScheduleInfo` 方法内部调用了 `setCurrentUser(projects)`，这个方法会：

1. 获取当前用户 ID
2. 判断用户是否为管理员（admin 或 gly 角色）
3. 将权限信息注入到查询对象

然后在 Mapper 层的 SQL 中：

```xml
<where>
    <!-- 统一的权限控制逻辑 -->
    <if test="isAdmin != null and isAdmin == true">
        <!-- 管理员查看所有项目 -->
        1=1
    </if>
    <if test="isAdmin == null or isAdmin == false">
        <!-- 非管理员只能查看参与的项目 -->
        <if test="currentUserId != null and currentUserId != ''">
            AND p.id IN (
                SELECT pm.project_id
                FROM project_members pm
                WHERE pm.user_id = #{currentUserId} AND pm.is_active = 1
            )
        </if>
    </if>
</where>
```

**结论**：
- ✅ 权限过滤已经内置在 `selectProjectsListWithScheduleInfo` 中
- ✅ 不需要额外传递 `includeProjectMembers` 参数
- ✅ 普通用户只能看到自己参与项目的进度统计

## 总结

### 问题根源

前端调用了错误的 API 参数，导致后端没有返回进度统计数据。

### 修复方法

将 `includeProjectMembers: true` 改为 `includeScheduleInfo: true`。

### 修复优势

1. ✅ 进度统计数据正确显示
2. ✅ 权限控制依然有效
3. ✅ 性能优化（批量查询）
4. ✅ 代码简洁（一个参数搞定）

### 注意事项

- 确保后端 `project_schedules` 表有数据
- 确保进度状态字段正确（COMPLETED、IN_PROGRESS 等）
- 如果项目没有进度，会显示 0/0，这是正常的
