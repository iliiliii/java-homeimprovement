| FileUpload | `src/components/FileUpload/index.vue` | 通用文件上传 | ✅ 80%质量 |

## 压缩配置

### 全局配置

所有组件都支持以下压缩相关属性：

```javascript
{
  compress: true,              // 是否启用压缩（默认：true）
  compressQuality: 0.8,        // 压缩质量 0.0-1.0（默认：0.7-0.9）
  compressMaxSize: 1,          // 压缩后最大文件大小 MB（默认：1）
  compressMaxWidthOrHeight: 1920  // 压缩后最大边长 px（默认：1920）
}
```

### 各组件默认配置

```javascript
// AvatarUpload
{
  compress: true,
```

## 重要说明

### ⚠️ 关键修复

如果需要修改或扩展上传逻辑，请遵循以下原则：

**❌ 错误做法**：
```javascript
// 不要在before-upload中尝试修改file参数
async function handleBeforeUpload(file) {
  const compressed = await compressImage(file)
  file = compressed.file  // 无效：只是局部变量修改
  return true
}
```

**✅ 正确做法**：
```javascript
// 使用http-request完全接管上传逻辑
<el-upload
  :http-request="customUploadHandler"  // 自定义上传函数
/>

// 在自定义函数中使用压缩后的文件
async function customUploadHandler(options) {
  const fileToUpload = compressedFile.value || options.file
  const formData = new FormData()
  formData.append('file', fileToUpload)
  // ... 发起请求
}
```

详细说明请参考：[图片压缩修复报告.md](./图片压缩修复报告.md)

## 故障排除

### 1. 压缩不生效

**检查项**：
- 确认`:compress="true"`
- 确认文件是图片类型
- 查看浏览器控制台是否有错误

**解决方案**：
- 确保使用`:http-request`自定义上传逻辑
- 不要在`before-upload`中尝试修改`file`参数

### 2. 上传失败

**检查项**：
- 检查服务器端接口是否正常
- 检查认证Token是否有效
- 查看网络请求和响应

**解决方案**：
- 查看`handleHttpRequest`中的错误处理
- 检查FormData是否正确创建

### 3. 内存泄漏

**检查项**：
- 上传后是否清理了`compressedFiles`缓存
- 多次上传是否累积未清理的缓存

**解决方案**：
- 在上传成功/失败后调用`compressedFiles.value.delete(file.uid)`
- 在组件卸载时清理所有缓存
