# 数据迁移与同步方案

**创建时间**: 2026-03-01  
**目标**: 将 projects.customer_id 数据迁移到 project_customers 表，并保持数据同步

---

## 📋 问题分析

### 1. 当前架构问题

#### 问题 1: 数据冗余
- `projects` 表中有 `customer_id` 字段（旧字段）
- `project_customers` 表中也有 `customer_id` 字段（新字段）
- 两个字段需要保持同步

#### 问题 2: 数据不一致风险
- 如果只修改 `projects.customer_id`，`project_customers` 表不会更新
- 如果只修改 `project_customers` 表，`projects.customer_id` 不会更新
- 可能导致数据不一致

#### 问题 3: 历史数据迁移
- 现有项目的 `customer_id` 需要迁移到 `project_customers` 表
- 需要设置为主客户（is_primary = 1）

---

## 🎯 解决方案

### 方案选择：使用数据库触发器自动同步

**优点**:
- ✅ 在数据库层面保证数据一致性
- ✅ 不需要修改应用代码
- ✅ 自动处理所有 INSERT/UPDATE 操作
- ✅ 性能影响小

**缺点**:
- ⚠️ 增加数据库复杂度
- ⚠️ 需要维护触发器

## 📝 完整 SQL 方案

### 步骤 1: 历史数据迁移

```sql
-- ============================================
-- 步骤 1: 历史数据迁移
-- 将现有的 projects.customer_id 迁移到 project_customers 表
-- ============================================

-- 1.1 迁移数据（只迁移尚未迁移的记录）
INSERT INTO project_customers (
    id, 
    project_id, 
    customer_id, 
    role, 
    is_primary, 
    created_at, 
    created_by
)
SELECT 
    REPLACE(UUID(), '-', ''),  -- 生成32位UUID（去掉横线）
    p.id AS project_id,
    p.customer_id,
    'OWNER' AS role,
    1 AS is_primary,  -- 设置为主客户
    p.created_at,
    p.created_by
FROM projects p
WHERE 
    p.customer_id IS NOT NULL 
    AND p.deleted_at IS NULL
    AND NOT EXISTS (
        -- 避免重复迁移
        SELECT 1 
        FROM project_customers pc 
        WHERE pc.project_id = p.id 
          AND pc.customer_id = p.customer_id
          AND pc.deleted_at IS NULL
    );

-- 1.2 验证迁移结果
SELECT 
    '迁移前 projects 表中有 customer_id 的记录数' AS description,
    COUNT(*) AS count
FROM projects 
WHERE customer_id IS NOT NULL AND deleted_at IS NULL

UNION ALL

SELECT 
    '迁移后 project_customers 表中的记录数' AS description,
    COUNT(*) AS count
FROM project_customers 
WHERE deleted_at IS NULL

UNION ALL

SELECT 
    '未迁移的记录数（应该为0）' AS description,
    COUNT(*) AS count
FROM projects p
WHERE 
    p.customer_id IS NOT NULL 
    AND p.deleted_at IS NULL
    AND NOT EXISTS (
        SELECT 1 
        FROM project_customers pc 
        WHERE pc.project_id = p.id 
          AND pc.customer_id = p.customer_id
          AND pc.deleted_at IS NULL
    );
```

### 步骤 2: 创建触发器（保持数据同步）

```sql
-- ============================================
-- 步骤 2: 创建触发器
-- 当 projects.customer_id 变化时，自动同步到 project_customers 表
-- ============================================

-- 2.1 删除旧触发器（如果存在）
DROP TRIGGER IF EXISTS trg_projects_customer_insert;
DROP TRIGGER IF EXISTS trg_projects_customer_update;
DROP TRIGGER IF EXISTS trg_projects_customer_delete;

-- 2.2 创建 INSERT 触发器
-- 当插入新项目时，自动在 project_customers 表中创建关联
DELIMITER $$

CREATE TRIGGER trg_projects_customer_insert
AFTER INSERT ON projects
FOR EACH ROW
BEGIN
    -- 只有当 customer_id 不为空时才创建关联
    IF NEW.customer_id IS NOT NULL THEN
        -- 检查是否已存在关联（避免重复）
        IF NOT EXISTS (
            SELECT 1 
            FROM project_customers 
            WHERE project_id = NEW.id 
              AND customer_id = NEW.customer_id
              AND deleted_at IS NULL
        ) THEN
            -- 插入新的客户关联
            INSERT INTO project_customers (
                id,
                project_id,
                customer_id,
                role,
                is_primary,
                created_at,
                created_by
            ) VALUES (
                REPLACE(UUID(), '-', ''),
                NEW.id,
                NEW.customer_id,
                'OWNER',
                1,  -- 设置为主客户
                NEW.created_at,
                NEW.created_by
            );
        END IF;
    END IF;
END$$

DELIMITER ;

-- 2.3 创建 UPDATE 触发器
-- 当更新项目的 customer_id 时，自动更新 project_customers 表
DELIMITER $$

CREATE TRIGGER trg_projects_customer_update
AFTER UPDATE ON projects
FOR EACH ROW
BEGIN
    -- 只有当 customer_id 发生变化时才处理
    IF OLD.customer_id != NEW.customer_id OR (OLD.customer_id IS NULL AND NEW.customer_id IS NOT NULL) THEN
        
        -- 1. 如果旧的 customer_id 不为空，软删除旧的关联
        IF OLD.customer_id IS NOT NULL THEN
            UPDATE project_customers
            SET deleted_at = NOW(),
                updated_at = NOW(),
                updated_by = NEW.updated_by
            WHERE project_id = NEW.id
              AND customer_id = OLD.customer_id
              AND deleted_at IS NULL;
        END IF;
        
        -- 2. 如果新的 customer_id 不为空，创建新的关联
        IF NEW.customer_id IS NOT NULL THEN
            -- 检查是否已存在关联
            IF NOT EXISTS (
                SELECT 1 
                FROM project_customers 
                WHERE project_id = NEW.id 
                  AND customer_id = NEW.customer_id
                  AND deleted_at IS NULL
            ) THEN
                -- 插入新的客户关联
                INSERT INTO project_customers (
                    id,
                    project_id,
                    customer_id,
                    role,
                    is_primary,
                    created_at,
                    created_by
                ) VALUES (
                    REPLACE(UUID(), '-', ''),
                    NEW.id,
                    NEW.customer_id,
                    'OWNER',
                    1,  -- 设置为主客户
                    NOW(),
                    NEW.updated_by
                );
            ELSE
                -- 如果已存在但被软删除，恢复它
                UPDATE project_customers
                SET deleted_at = NULL,
                    updated_at = NOW(),
                    updated_by = NEW.updated_by,
                    is_primary = 1
                WHERE project_id = NEW.id
                  AND customer_id = NEW.customer_id
                  AND deleted_at IS NOT NULL;
            END IF;
        END IF;
    END IF;
END$$

DELIMITER ;

-- 2.4 创建 DELETE 触发器（软删除）
-- 当软删除项目时，同时软删除 project_customers 中的关联
DELIMITER $$

CREATE TRIGGER trg_projects_customer_delete
AFTER UPDATE ON projects
FOR EACH ROW
BEGIN
    -- 只有当 deleted_at 从 NULL 变为非 NULL 时才处理（软删除）
    IF OLD.deleted_at IS NULL AND NEW.deleted_at IS NOT NULL THEN
        -- 软删除所有相关的客户关联
        UPDATE project_customers
        SET deleted_at = NEW.deleted_at,
            updated_at = NOW(),
            updated_by = NEW.updated_by
        WHERE project_id = NEW.id
          AND deleted_at IS NULL;
    END IF;
    
    -- 如果项目被恢复（deleted_at 从非 NULL 变为 NULL）
    IF OLD.deleted_at IS NOT NULL AND NEW.deleted_at IS NULL THEN
        -- 恢复所有相关的客户关联
        UPDATE project_customers
        SET deleted_at = NULL,
            updated_at = NOW(),
            updated_by = NEW.updated_by
        WHERE project_id = NEW.id
          AND deleted_at IS NOT NULL;
    END IF;
END$$

DELIMITER ;
```

### 步骤 4: 数据一致性检查

```sql
-- ============================================
-- 步骤 4: 数据一致性检查
-- 检查 projects 和 project_customers 表的数据是否一致
-- ============================================

-- 4.1 检查 projects 表中有 customer_id 但 project_customers 表中没有对应记录的项目
SELECT 
    p.id AS project_id,
    p.name AS project_name,
    p.customer_id,
    '缺少 project_customers 记录' AS issue
FROM projects p
WHERE 
    p.customer_id IS NOT NULL 
    AND p.deleted_at IS NULL
    AND NOT EXISTS (
        SELECT 1 
        FROM project_customers pc 
        WHERE pc.project_id = p.id 
          AND pc.customer_id = p.customer_id
          AND pc.deleted_at IS NULL
    );

-- 4.2 检查 project_customers 表中的主客户是否与 projects.customer_id 一致
SELECT 
    p.id AS project_id,
    p.name AS project_name,
    p.customer_id AS projects_customer_id,
    pc.customer_id AS pc_customer_id,
    '主客户不一致' AS issue
FROM projects p
INNER JOIN project_customers pc ON p.id = pc.project_id
WHERE 
    p.deleted_at IS NULL
    AND pc.deleted_at IS NULL
    AND pc.is_primary = 1
    AND p.customer_id != pc.customer_id;

-- 4.3 检查是否有项目没有主客户
SELECT 
    p.id AS project_id,
    p.name AS project_name,
    '没有主客户' AS issue
FROM projects p
WHERE 
    p.deleted_at IS NULL
    AND NOT EXISTS (
        SELECT 1 
        FROM project_customers pc 
        WHERE pc.project_id = p.id 
          AND pc.is_primary = 1
          AND pc.deleted_at IS NULL
    );

-- 4.4 检查是否有项目有多个主客户（不应该存在）
SELECT 
    pc.project_id,
    COUNT(*) AS primary_customer_count,
    '有多个主客户' AS issue
FROM project_customers pc
WHERE 
    pc.is_primary = 1
    AND pc.deleted_at IS NULL
GROUP BY pc.project_id
HAVING COUNT(*) > 1;
```

## ⚠️ 潜在问题分析

### 问题 1: projects.customer_id 字段是否保留？

**建议**: 保留但标记为废弃

**原因**:
1. ✅ 向后兼容 - 不影响现有代码
2. ✅ 数据冗余 - 通过触发器自动同步
3. ✅ 查询性能 - 某些简单查询可以直接使用
4. ✅ 过渡期 - 给代码迁移留出时间

**未来计划**:
- 在所有代码迁移完成后，可以考虑删除 `projects.customer_id` 字段
- 或者保留作为冗余字段，提高查询性能

---

### 问题 2: 修改 projects.customer_id 时的数据同步

**场景**: 用户通过管理后台修改项目的客户

**解决方案**: 触发器自动处理

**流程**:
1. 用户修改 `projects.customer_id`
2. UPDATE 触发器自动触发
3. 软删除旧的 `project_customers` 记录
4. 创建新的 `project_customers` 记录（设置为主客户）
5. 数据保持一致

---

### 问题 3: 通过 project_customers 表添加客户时的同步

**场景**: 用户通过新的多客户管理功能添加客户

**问题**: `projects.customer_id` 不会自动更新

**解决方案**: 在应用代码中处理

**建议**:
1. 当设置主客户时，同时更新 `projects.customer_id`
2. 在 `ProjectCustomersServiceImpl.setPrimaryCustomer` 方法中添加逻辑

**代码示例**:
```java
@Override
@Transactional(rollbackFor = Exception.class)
public int setPrimaryCustomer(String projectId, String customerId) {
    // ... 现有代码 ...
    
    // 同步更新 projects.customer_id
    Projects project = new Projects();
```

### 问题 4: 性能影响

**触发器性能影响**:
- ✅ INSERT 触发器：每次插入项目时执行一次 INSERT（影响小）
- ✅ UPDATE 触发器：只有当 customer_id 变化时才执行（影响小）
- ✅ DELETE 触发器：软删除时执行一次 UPDATE（影响小）

**优化建议**:
- ✅ 已添加索引（project_id, customer_id）
- ✅ 使用 EXISTS 子查询避免重复插入
- ✅ 只在必要时执行操作

---

### 问题 5: 数据一致性保证

**风险点**:
1. 触发器失败导致数据不一致
2. 直接操作数据库绕过触发器
3. 触发器被禁用或删除

**解决方案**:
1. ✅ 定期运行数据一致性检查 SQL（步骤 4）
2. ✅ 在应用层添加数据验证
3. ✅ 监控触发器状态
4. ✅ 在关键操作中添加事务
