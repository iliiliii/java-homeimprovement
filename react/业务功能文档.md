#### 进度计算逻辑

```typescript
// Progress.tsx:29-41
function calculateProgress(project: Project) {
  const completedSteps = project.timeline.filter(t => t.status === 'completed').length;
  const inProgressSteps = project.timeline.filter(t => t.status === 'inProgress').length;
  const totalSteps = project.timeline.length;
  const progressPercentage = (completedSteps / totalSteps) * 100;

  return { completedSteps, inProgressSteps, totalSteps, progressPercentage };
}

// 业务规则:
// • 进度 = (已完成阶段数 / 总阶段数) × 100%
// • 只统计"已完成"状态,不统计"进行中"
// • 所有阶段完成 = 100%进度
```

### 6.2 关键业务规则总结

```
业务规则清单:
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

客户管理规则:
✓ 客户必填项: 姓名、电话、邮箱、地址
✓ 客户可关联多个项目,删除客户不删除项目
✓ 活跃客户定义: 有任何进行中项目的客户
✓ 重点客户算法: 按项目数量降序排序Top5

项目管理规则:
✓ 项目必须关联客户(customerId必填)
✓ 项目初始状态固定为"规划中"
✓ 总预算 = Σ(各分类预算金额)
✓ 项目状态流转规则:
  • 规划中 → 进行中 (开始项目)
  • 进行中 → 暂停 (暂停项目)
  • 进行中 → 已完成 (完成项目)
  • 暂停 → 进行中 (恢复项目)
  • 已完成为终态,不可回退

进度跟踪规则:
✓ 进度计算公式: (已完成阶段数 / 总阶段数) × 100%
✓ 只统计"已完成"状态,不计"进行中"
✓ 验收记录可以多条,不影响阶段状态
✓ 只显示"进行中"状态的项目

质量管控规则:
✓ 同一项目同一天只有一条质检记录
✓ 质检状态自动判断:
  if (所有issues都resolved) { status = 'passed' }
  else { status = 'failed' }
✓ 问题整改前状态为"pending",整改后为"resolved"
✓ 质检通过率 = (passed数 / 总质检数) × 100%

团队管理规则:
✓ 角色限制为4类: 设计师/项目经理/工长/监理
✓ 手机号必须为11位有效号码
✓ 项目团队每个角色可分配多人
✓ 团队成员删除不影响已关联项目(仅解除关联)

数据看板规则:
✓ 活跃客户 = 有进行中项目的客户
✓ 合同总额 = Σ(所有项目totalBudget)
✓ 重点客户 = 按项目数排序取Top5
✓ 待办事项:
  • 规划中项目 > 0 → 显示"待启动"提示
  • 质检不通过 > 0 → 显示"问题待处理"提示
```
