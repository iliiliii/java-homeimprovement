# 项目多客户关联 - 潜在问题分析与修复方案

## 一、核心问题识别

### 问题1: 权限检查不完整 ⚠️

**现状**: 多处代码仍然只检查 `projects.customer_id`，没有检查 `project_customers` 表

**影响范围**:
```java
// ❌ 错误示例 - 只检查了 projects 表
if ("customer".equals(userType)) {
    Projects project = projectMapper.selectProjectById(projectId);
    if (project == null || !userId.equals(project.getCustomerId())) {
        throw new ServiceException("无权访问该项目");
    }
}
```

**问题**: 
- 非主客户无法访问项目（即使在 project_customers 表中有关联）
- 导致多客户功能失效

### 问题2: 查询逻辑不一致

**现状**: 不同地方使用不同的查询逻辑

**影响**:
- 登录时查询项目列表：使用 `project_customers` 表 ✅
- 权限验证时：使用 `projects.customer_id` ❌
- 导致数据不一致

### 问题3: 数据同步问题

**现状**: `projects.customer_id` 与 `project_customers` 表可能不同步

**风险**:
- 主客户变更后，`projects.customer_id` 未更新
- 导致查询结果错误

### 问题4: 缓存失效问题

**现状**: Token 中的项目列表可能过期

**影响**:
- 客户被添加到项目后，Token 中没有该项目ID
- 需要重新登录才能访问

## 二、完整修复方案

### 2.1 统一权限检查工具类

创建统一的权限检查工具，确保所有地方使用相同逻辑。

```java
package com.ruoyi.app.utils;

import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.stereotype.Component;
import com.ruoyi.app.mapper.AppDashboardMapper;
import com.ruoyi.web.mapper.ProjectCustomersMapper;

/**
 * 项目权限检查工具类
 */
@Component
public class ProjectAccessChecker {
    
    @Autowired
    private ProjectCustomersMapper projectCustomersMapper;
    
    @Autowired
    private AppDashboardMapper dashboardMapper;
    
    /**
     * 检查用户是否有权访问项目
     * 
     * @param projectId 项目ID
     * @param userId 用户ID
     * @param userType 用户类型（customer/staff）
     * @return true=有权限，false=无权限
     */
    public boolean checkProjectAccess(String projectId, String userId, String userType) {
        if (projectId == null || userId == null || userType == null) {
            return false;
        }
        
        if ("customer".equals(userType)) {
            // 客户：检查 project_customers 表
            return projectCustomersMapper.checkCustomerInProject(projectId, userId);
        } else if ("staff".equals(userType)) {
            // 员工：检查 project_members 表
            return dashboardMapper.checkStaffProjectAccess(userId, projectId);
        }
        
        return false;
    }
    
    /**
     * 检查用户是否为项目的主客户
     */
    public boolean isPrimaryCustomer(String projectId, String userId) {
        if (projectId == null || userId == null) {
            return false;
        }
        
        ProjectCustomers primary = projectCustomersMapper.selectPrimaryByProjectId(projectId);
        return primary != null && userId.equals(primary.getCustomerId());
    }
    
    /**
     * 获取用户在项目中的角色
     */
    public String getCustomerRole(String projectId, String userId) {
        List<ProjectCustomers> list = projectCustomersMapper.selectByProjectId(projectId);
        for (ProjectCustomers pc : list) {
            if (userId.equals(pc.getCustomerId())) {
                return pc.getRole();
            }
        }
        return null;
    }
}
```

### 2.4 数据同步机制

#### 方案A: 触发器自动同步（推荐）

```sql
-- 创建触发器：当 project_customers 的主客户变更时，自动更新 projects 表
DELIMITER $$

CREATE TRIGGER sync_primary_customer_after_insert
AFTER INSERT ON project_customers
FOR EACH ROW
BEGIN
    IF NEW.is_primary = 1 THEN
        UPDATE projects 
        SET customer_id = NEW.customer_id,
            updated_at = NOW()
        WHERE id = NEW.project_id;
    END IF;
END$$

CREATE TRIGGER sync_primary_customer_after_update
AFTER UPDATE ON project_customers
FOR EACH ROW
BEGIN
    IF NEW.is_primary = 1 AND (OLD.is_primary = 0 OR OLD.is_primary IS NULL) THEN
        UPDATE projects 
        SET customer_id = NEW.customer_id,
            updated_at = NOW()
        WHERE id = NEW.project_id;
    END IF;
END$$

DELIMITER ;
```

#### 方案B: Service层同步（备选）

```java
@Service
public class ProjectCustomersServiceImpl implements IProjectCustomersService {
    
    @Override
    @Transactional(rollbackFor = Exception.class)
    public int setPrimaryCustomer(String projectId, String customerId) {
        // 1. 设置主客户
        int result = projectCustomersMapper.setPrimaryCustomer(projectId, customerId);
        
        // 2. 同步更新 projects 表
        syncPrimaryCustomerToProjects(projectId, customerId);
        
        return result;
    }
    
    /**
     * 同步主客户到 projects 表
     */
    private void syncPrimaryCustomerToProjects(String projectId, String customerId) {
        Projects project = new Projects();
        project.setId(projectId);
        project.setCustomerId(customerId);
        project.setUpdatedAt(new Date());
        project.setUpdatedBy(SecurityUtils.getUsername());
        
        projectsMapper.updateProjects(project);
        
        log.info("同步主客户到projects表: projectId={}, customerId={}", projectId, customerId);
    }
}
```

### 2.5 Token刷新机制

#### 问题场景
```
1. 客户A登录，Token中包含项目列表 [P1, P2]
2. 管理员将客户A添加到项目P3
3. 客户A访问P3 → 权限验证通过（project_customers表有记录）
4. 但Token中没有P3 → 某些依赖Token的功能可能失败
```

#### 解决方案A: 实时查询（推荐）

```java
/**
 * 不依赖Token中的项目列表，每次都实时查询
```

#### 解决方案B: Token自动刷新

```java
/**
 * 检测到项目列表变化时，提示用户刷新Token
 */
@Override
public List<AppProjectInfo> getMyProjects(String authorization) {
    Map<String, Object> claims = tokenManager.validateToken(extractToken(authorization));
    String userType = (String) claims.get("userType");
    String userId = claims.get("userId").toString();
    
    // 从Token中获取项目列表
    List<String> tokenProjectIds = (List<String>) claims.get("projectIds");
    
    // 实时查询项目列表
    List<AppProjectInfo> actualProjects = findUserProjects(
        UserTypeEnum.fromCode(userType), userId
    );
    
    // 比对差异
    Set<String> actualProjectIds = actualProjects.stream()
        .map(AppProjectInfo::getId)
        .collect(Collectors.toSet());
    
    if (!actualProjectIds.equals(new HashSet<>(tokenProjectIds))) {
        // 项目列表已变化，建议刷新Token
        log.warn("用户 {} 的项目列表已变化，建议刷新Token", userId);
        // 可以在响应头中添加提示
        // response.setHeader("X-Token-Refresh-Required", "true");
    }
    
    return actualProjects;
}
```

## 五、数据一致性检查SQL

```sql
-- 检查 projects.customer_id 与 project_customers 主客户是否一致
SELECT 
    p.id as project_id,
    p.name as project_name,
    p.customer_id as projects_customer_id,
    pc.customer_id as primary_customer_id,
    c1.name as projects_customer_name,
    c2.name as primary_customer_name,
    CASE 
        WHEN p.customer_id = pc.customer_id THEN '一致'
        WHEN p.customer_id IS NULL AND pc.customer_id IS NOT NULL THEN 'projects表缺失'
        WHEN p.customer_id IS NOT NULL AND pc.customer_id IS NULL THEN 'project_customers表缺失'
        ELSE '不一致'
    END as status
FROM projects p
LEFT JOIN (
    SELECT project_id, customer_id 
    FROM project_customers 
    WHERE is_primary = 1 AND is_active = 1
) pc ON p.id = pc.project_id
LEFT JOIN customers c1 ON p.customer_id = c1.id
LEFT JOIN customers c2 ON pc.customer_id = c2.id
WHERE p.deleted_at IS NULL
  AND (p.customer_id != pc.customer_id OR p.customer_id IS NULL OR pc.customer_id IS NULL)
ORDER BY p.created_at DESC;
```

## 八、总结

### 核心问题
当前方案中最大的问题是**权限检查逻辑不统一**，部分代码仍然只检查 `projects.customer_id`，导致多客户功能失效。

### 解决方案
1. **创建统一的权限检查工具类** - 确保所有地方使用相同逻辑
2. **修改所有权限验证点** - 使用 `project_customers` 表检查权限
3. **添加数据同步机制** - 保证 `projects.customer_id` 与主客户一致
4. **完善测试用例** - 覆盖所有权限场景

### 实施建议
1. 先创建工具类和修改权限检查（P0）
2. 再添加数据同步机制（P1）
3. 最后优化性能和用户体验（P2）
