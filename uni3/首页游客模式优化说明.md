# 首页游客模式优化说明

## 优化概述

根据需求对首页 `uni3/src/pages/dashboard/index.vue` 进行了优化，实现了未登录用户和游客模式用户都显示游客页面组件，登录后根据用户角色显示对应的主页。

## 主要优化内容

### 1. 页面显示逻辑重构

#### 新的显示规则
- **未登录用户** → 显示游客页面（CustomerDashboard组件，无项目数据）
- **游客模式用户** → 显示游客页面（CustomerDashboard组件，无项目数据）
- **已登录客户** → 显示客户主页（CustomerDashboard组件，有项目数据）
- **已登录员工** → 显示员工主页（StaffDashboard组件）

#### 核心判断逻辑
```javascript
// 判断是否显示游客页面
const shouldShowGuestView = computed(() => {
  const isGuest = uni.getStorageSync('guestMode') === true
  const isLoggedIn = userStore.isLoggedIn
  
  // 未登录用户或游客模式用户显示游客页面
  return !isLoggedIn || isGuest
})
```

### 2. 模板结构优化

```vue
<template>
  <view class="dashboard-page">
    <!-- 游客页面（未登录用户和游客模式用户） -->
    <CustomerDashboard 
      v-if="shouldShowGuestView"
      :projects="[]"
      :current-project="null"
    />
    
    <!-- 客户视图（已登录的客户） -->
    <CustomerDashboard 
      v-else-if="userType === 'customer'"
      :projects="projects"
      :current-project="currentProject"
    />
    
    <!-- 员工视图（已登录的员工） -->
    <StaffDashboard 
      v-else-if="userType === 'staff'"
      :projects="staffProjects"
    />
  </view>
</template>
```

### 3. 初始化逻辑优化

#### 原逻辑问题
- 游客模式用户被强制设置为客户类型
- 未登录用户显示"请先登录"的空白页面
- 逻辑混乱，难以维护

#### 新逻辑优势
```javascript
onMounted(async () => {
  userStore.initFromStorage()
  
  // 如果需要显示游客页面，直接显示，不加载用户数据
  if (shouldShowGuestView.value) {
    console.log('[Dashboard] 显示游客页面')
    userType.value = 'guest' // 设置为游客类型
    loading.value = false
    return
  }
  
  // 已登录用户，设置用户类型并加载数据
  userType.value = userStore.userType
  await loadDashboardData()
})
```

### 4. CustomerDashboard组件优化

#### 游客模式提示优化
```vue
<!-- 无项目提示（游客模式或无项目时显示） -->
<view v-else-if="isGuestMode" class="no-project-tip">
  <view class="tip-icon">🏠</view>
  <text class="tip-text">登录后可查看您的项目进度</text>
  <view class="tip-action" @click="goToLogin">
    <text>立即登录</text>
  </view>
</view>

<!-- 已登录但无项目的提示 -->
<view v-else-if="!isGuestMode && projects.length === 0" class="no-project-tip">
  <view class="tip-icon">📋</view>
  <text class="tip-text">暂无关联项目，请联系管理员</text>
</view>
```

#### 功能特点
- **游客用户**：显示登录引导，点击跳转登录页
- **已登录无项目用户**：显示联系管理员提示
- **已登录有项目用户**：正常显示项目卡片

### 5. 数据加载优化

#### 按需加载策略
- **游客页面**：只加载公共数据（Banner、资讯），不加载用户项目数据
- **客户页面**：加载用户项目数据和公共数据
- **员工页面**：加载员工项目列表数据

#### 刷新逻辑优化
```javascript
// 下拉刷新
onPullDownRefresh(async () => {
  // 游客页面不需要刷新用户数据，只刷新资讯等公共数据
  if (shouldShowGuestView.value) {
    // 游客页面的刷新由CustomerDashboard组件内部处理
    uni.stopPullDownRefresh()
    return
  }
  
  await loadDashboardData(true)
  uni.stopPullDownRefresh()
})
```

## 技术实现细节

### 1. 状态管理
- 使用计算属性 `shouldShowGuestView` 统一判断显示逻辑
- 游客模式设置 `userType.value = 'guest'` 便于调试和维护
- 保持原有的用户状态管理逻辑不变

### 2. 组件复用
- 复用 `CustomerDashboard` 组件作为游客页面
- 通过传入空的 `projects` 数组实现游客模式
- 组件内部根据 `isGuestMode` 显示不同的提示内容

### 3. 性能优化
- 游客模式不发起用户数据请求，减少网络开销
- 按需加载数据，避免无效的API调用
- 保持页面响应速度

## 用户体验提升

### 1. 统一的视觉体验
- 所有用户都能看到一致的页面结构（Banner + 资讯）
- 游客和已登录用户的界面风格保持一致
- 平滑的登录转换体验

### 2. 清晰的操作引导
- 游客用户有明确的登录引导
- 已登录无项目用户有明确的联系管理员提示
- 避免了空白页面和困惑

### 3. 合理的功能分层
- 公共功能（Banner、资讯）对所有用户开放
- 个人功能（项目进度）需要登录后查看
- 符合业务逻辑和用户预期

4. **错误处理**：需要处理网络请求失败等异常情况
