# 微信登录开发模式配置说明

## 问题描述

在开发环境中测试"导入历史数据"功能时，出现以下错误：
```
检查绑定接口错误: Error: 检查绑定状态失败: 微信登录失败: invalid appid
```

## 原因分析

这个错误发生的原因是：

1. **开发环境限制**：在非微信小程序环境（如浏览器H5、模拟器）中，`uni.login()` 获取的 code 是无效的
2. **微信API验证**：后端使用这个无效的 code 调用微信 API 时，微信服务器返回 "invalid appid" 错误
3. **真实环境需求**：只有在真实的微信小程序环境中，才能获取有效的 code

## 解决方案

### 方案1：启用开发模式（推荐）

后端已经实现了开发模式，可以跳过微信 API 调用，使用模拟数据进行测试。

#### 配置步骤

修改 `sb3/ruoyi-admin/src/main/resources/application.yml`：

```yaml
# 小程序配置
app:
  wechat:
    # 小程序AppID
    appid: wx607d3206ed1ec9e6
    # 小程序AppSecret
    secret: b29baa7cbcb773684226d35b188bebd0
    # 开发模式：跳过微信API调用，使用模拟数据
    dev-mode: true  # 改为 true
```

#### 开发模式行为

启用开发模式后：

1. **跳过微信API**：不会调用微信的 `code2session` 接口
2. **生成模拟openid**：基于 code 生成固定的 openid（同一个 code 总是返回相同的 openid）
3. **返回模拟数据**：
   ```java
   openid: "mock_openid_" + (code的hash值 % 10000)
   unionid: "mock_unionid_" + (code的hash值 % 1000)
   sessionKey: "mock_session_key"
   ```

#### 优点

- ✅ 可以在任何环境下测试（H5、模拟器、浏览器）
- ✅ 不需要真实的微信小程序环境
- ✅ 测试数据稳定可预测
- ✅ 可以测试完整的绑定流程

#### 缺点

- ❌ 无法测试真实的微信登录
- ❌ 需要记得在生产环境关闭

### 方案2：使用真实微信小程序环境

在真实的微信小程序环境中测试，需要：

1. **使用微信开发者工具**
   - 下载并安装微信开发者工具
   - 导入 uni3 项目
   - 配置正确的 AppID
   - 在真机或模拟器中测试

2. **确保配置正确**
   - 前端 `manifest.json` 中的 `mp-weixin.appid` 与后端配置一致
   - 后端 `application.yml` 中的 `app.wechat.appid` 和 `secret` 正确
   - 后端 `app.wechat.dev-mode` 设置为 `false`

3. **小程序配置**
   - 在微信公众平台配置服务器域名
   - 添加后端 API 域名到 request 合法域名

#### 优点

- ✅ 测试真实的微信登录流程
- ✅ 可以验证微信API集成
- ✅ 接近生产环境

#### 缺点

- ❌ 需要真实的微信小程序账号
- ❌ 需要配置域名和证书
- ❌ 开发调试不方便

## 推荐的开发流程

### 开发阶段
```yaml
# application.yml
app:
  wechat:
    dev-mode: true  # 启用开发模式
```

在开发阶段使用开发模式，可以快速测试：
- 游客模式登录
- 导入历史数据流程
- 账号绑定逻辑
- 错误处理
- 数据刷新

### 测试阶段
```yaml
# application.yml
app:
  wechat:
    dev-mode: false  # 关闭开发模式
```

在测试阶段使用真实环境，验证：
- 真实的微信登录
- 微信API集成
- 用户体验流程

### 生产环境
```yaml
# application.yml
app:
  wechat:
    dev-mode: false  # 必须关闭开发模式
    appid: <真实的AppID>
    secret: <真实的AppSecret>
```

## 注意事项

1. **开发模式的 openid 是模拟的**
   - 每次使用相同的 code 会得到相同的 openid
   - 不同的 code 会得到不同的 openid
   - 这对测试绑定逻辑是足够的

2. **生产环境必须关闭开发模式**
   - 否则所有用户都会使用模拟的 openid
   - 会导致用户数据混乱

3. **开发模式不影响其他功能**
   - 只影响微信登录相关的 API
   - 其他业务逻辑正常运行

4. **日志输出**
   - 开发模式会在日志中输出 "开发模式：模拟微信登录"
   - 方便识别当前是否在开发模式
