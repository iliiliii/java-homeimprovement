# 登录页面游客模式跳转修正说明

## 问题描述

用户在个人中心点击"立即登录"跳转到登录页面后，登录页面检测到游客模式就直接跳转回首页，没有给用户进行登录操作的机会。

## 问题分析

### 错误的逻辑流程
1. 游客用户在个人中心点击"立即登录"
2. 跳转到登录页面 `/pages/login/index-new`
3. 登录页面 `onMounted` 检测到 `guestMode: true`
4. **直接跳转回首页** ❌
5. 用户无法进行登录操作

### 原有的错误逻辑
```javascript
// 检查是否是游客模式
const isGuest = uni.getStorageSync('guestMode')
if (isGuest) {
  // 游客模式，直接跳转首页 ❌ 错误逻辑
  console.log('[登录页面] 检测到游客模式，跳转首页')
  uni.reLaunch({ url: '/pages/dashboard/index' })
  return
}
```

### 逻辑错误分析
这个逻辑的问题在于：
- **游客模式用户也需要登录功能**
- **不应该阻止游客用户进行登录**
- **应该让游客用户能够升级为正式用户**

## 修正方案

### 修正后的逻辑
```javascript
// 检查是否是游客模式
const isGuest = uni.getStorageSync('guestMode')
if (isGuest) {
  // 游客模式用户可以进行登录，显示登录界面 ✅ 正确逻辑
  console.log('[登录页面] 检测到游客模式，显示登录界面供用户登录')
  bindingStep.value = 'normal'
  return
}
```

### 修正后的流程
1. 游客用户在个人中心点击"立即登录"
2. 跳转到登录页面 `/pages/login/index-new`
3. 登录页面检测到 `guestMode: true`
4. **显示登录界面供用户登录** ✅
5. 用户可以进行微信登录操作
6. 登录成功后根据绑定状态进行相应处理

## 用户体验优化

### 修正前的问题体验
```
游客用户 → 点击登录 → 登录页面 → 自动跳转回首页 → 用户困惑 ❌
```

### 修正后的正确体验
```
游客用户 → 点击登录 → 登录页面 → 显示登录按钮 → 进行登录 → 成功登录 ✅
```

## 登录页面的完整逻辑

### 页面初始化检查顺序
1. **主动退出检查**：如果是主动退出，显示登录界面
2. **游客模式检查**：如果是游客模式，显示登录界面（修正后）
3. **Token检查**：如果有有效token，验证后跳转
4. **默认行为**：显示登录界面

### 各种用户状态的处理
| 用户状态 | guestMode | token | 页面行为 |
|---------|-----------|-------|---------|
| 未登录普通用户 | false | 无 | 显示登录界面 |
| **游客模式用户** | **true** | **无** | **显示登录界面** |
| 已登录用户 | false | 有 | 验证后跳转首页 |
| 主动退出用户 | - | - | 显示登录界面 |

## 登录成功后的处理

### 游客登录成功的两种情况

#### 1. 已绑定后台账户
- 清除 `guestMode` 标记
- 设置 `wasGuestMode` 标记
- 保存用户登录信息
- 跳转到对应角色的首页

#### 2. 未绑定后台账户
- 清除 `guestMode` 标记
- 设置 `wasGuestMode` 标记
- 创建游客登录状态（`userType: 'guest'`）
- 跳转到首页，显示导入数据引导
