# 游客用户项目卡片隐藏优化说明

## 优化需求

游客用户（`userType: "guest"`）登录成功后，在首页不应该显示项目卡片区域，而应该显示引导用户导入历史数据的提示。

## 问题分析

### 原有逻辑的问题
1. **游客模式判断不准确**：只基于 `guestMode` 存储标记判断
2. **已登录游客用户识别错误**：登录成功后 `guestMode` 被清除，导致游客用户被当作普通客户
3. **项目卡片显示逻辑不当**：游客用户仍然显示项目卡片区域

### 修正前的逻辑
```javascript
// 只判断未登录的游客模式
const isGuestMode = computed(() => uni.getStorageSync('guestMode') === true)

// 有项目就显示项目卡片
<ProjectCardSwiper v-if="projects.length > 0" />
```

## 优化方案

### 1. 优化游客模式判断逻辑

#### 修正后的判断
```javascript
// 游客模式判断（包括未登录游客和已登录游客用户）
const isGuestMode = computed(() => {
  // 未登录的游客模式
  const guestMode = uni.getStorageSync('guestMode') === true
  // 已登录的游客用户
  const isGuestUser = userStore.userType === 'guest'
  
  return guestMode || isGuestUser
})
```

#### 覆盖的场景
- **未登录游客**：`guestMode: true, userType: ""`
- **已登录游客**：`guestMode: false, userType: "guest"`
- **正式客户**：`guestMode: false, userType: "customer"`

### 2. 优化项目卡片显示逻辑

#### 修正后的显示条件
```vue
<!-- 项目卡片滑动区域（仅在有项目且非游客用户时显示） -->
<ProjectCardSwiper
  v-if="projects.length > 0 && !isGuestMode"
  :projects="projects"
  :user-info="userInfo"
  :current="currentIndex"
  @update:current="index => currentIndex = index"
  @change="handleSwiperChange"
  @click="handleCardClick"
/>
```

#### 显示规则
- **有项目 + 非游客用户** → 显示项目卡片
- **游客用户（不论是否有项目）** → 不显示项目卡片，显示引导提示

### 3. 优化提示信息显示

#### 智能提示逻辑
```vue
<!-- 游客用户提示（已登录游客或未登录游客） -->
<view v-else-if="isGuestMode" class="no-project-tip">
  <view class="tip-icon">🏠</view>
  <text class="tip-text">
    {{ userStore.isLoggedIn ? '导入历史数据后可查看您的项目' : '登录后可查看您的项目进度' }}
  </text>
  <view v-if="!userStore.isLoggedIn" class="tip-action" @click="goToLogin">
    <text>立即登录</text>
  </view>
  <view v-else class="tip-action" @click="goToProfile">
    <text>去导入数据</text>
  </view>
</view>
```

#### 提示内容区分
- **未登录游客**：显示"登录后可查看您的项目进度" + "立即登录"按钮
- **已登录游客**：显示"导入历史数据后可查看您的项目" + "去导入数据"按钮

### 4. 添加跳转功能

```javascript
// 跳转到登录页面
const goToLogin = () => {
  uni.navigateTo({ url: '/pages/login/index-new' })
}

// 跳转到个人中心导入数据
const goToProfile = () => {
  uni.switchTab({ url: '/pages/profile/index' })
}
```

## 优化后的显示逻辑

### 页面显示规则

| 用户状态 | 项目数据 | 项目卡片 | 提示内容 | 操作按钮 |
|---------|---------|---------|---------|---------|
| 未登录游客 | 无 | ❌ | 登录后可查看项目进度 | 立即登录 |
| 已登录游客 | 无 | ❌ | 导入历史数据后可查看项目 | 去导入数据 |
| 正式客户(有项目) | 有 | ✅ | - | - |
| 正式客户(无项目) | 无 | ❌ | 暂无关联项目，请联系管理员 | - |

### 用户体验流程

1. **未登录游客访问首页**
   - 看到：Banner + 登录引导 + 资讯
   - 点击"立即登录" → 跳转登录页

2. **游客登录成功后访问首页**
   - 看到：Banner + 导入数据引导 + 资讯
   - 点击"去导入数据" → 跳转个人中心

3. **游客导入数据成功后访问首页**
   - 看到：Banner + 项目卡片 + 资讯
   - 正常使用项目功能

## 技术实现细节

### 1. 状态判断优化
- 使用 `userStore.userType` 准确识别用户类型
- 结合存储标记和用户状态进行综合判断
- 避免状态不一致导致的显示错误

### 2. 条件渲染优化
- 使用 `v-if` 和 `v-else-if` 确保互斥显示
- 明确的显示优先级：项目卡片 > 游客提示 > 客户提示
- 避免多个组件同时显示

### 3. 用户引导优化
- 根据登录状态显示不同的引导文案
- 提供明确的操作按钮和跳转路径
- 保持用户操作的连贯性

## 测试验证

### 需要验证的场景

1. **未登录游客访问首页**
   - 不应显示项目卡片
   - 应显示"登录后可查看项目进度"
   - 点击按钮应跳转登录页

2. **游客登录成功后访问首页**
   - 不应显示项目卡片（即使传入了项目数据）
   - 应显示"导入历史数据后可查看项目"
   - 点击按钮应跳转个人中心

3. **游客导入数据成功后访问首页**
   - 应显示项目卡片（如果有项目数据）
   - 不应显示游客提示

4. **正式客户访问首页**
   - 有项目时显示项目卡片
   - 无项目时显示"暂无关联项目"提示

## 注意事项

1. **状态一致性**：确保 `userStore.userType` 与实际用户状态保持一致
2. **数据传递**：游客用户仍然会接收到空的项目数组，但不会显示项目卡片
3. **用户体验**：保持引导流程的连贯性，避免用户困惑
4. **性能考虑**：避免不必要的组件渲染和数据处理
