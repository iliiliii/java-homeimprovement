# 账号文案统一修改说明

## 修改目标

将所有"手机号"相关的文案统一改为"账号"，让用户感觉更加中性和专业，避免过于明确地暴露账号体系是基于手机号的。

## 修改原因

1. **更加中性** - "账号"比"手机号"更通用
2. **更加专业** - 符合系统化的表述习惯
3. **避免敏感** - 不直接暴露账号体系的实现细节
4. **用户友好** - 用户更容易理解"账号"的概念

## 修改内容

### 1. 个人中心页面 (profile/index.vue)

#### 修改1：错误提示对话框

## 保持不变的地方

### 1. 变量名和函数名
```javascript
// 保持原有的变量名，不影响代码逻辑
const phoneNumber = ref('')
const isValidPhone = computed(() => ...)
const handlePhoneConfirm = async (phone) => {}
```

**原因：**
- 变量名是内部实现细节
- 修改变量名需要大量重构
- 不影响用户体验

### 2. CSS类名
```scss
.phone-modal
.phone-input
.phone-modal-overlay
```

**原因：**
- CSS类名是内部实现
- 不会显示给用户
- 保持代码一致性

### 3. 输入框类型
```vue
<input type="tel" />
```

**原因：**
- `type="tel"` 会调起数字键盘
- 方便用户输入
- 不影响显示文案

### 4. 国家代码显示
```vue
<text class="country-code">+86</text>
```

**原因：**
- 保留 +86 前缀
- 暗示是手机号格式
- 但不在文案中明确说明

## 审核合规性

### 符合微信规范
1. **不强调手机号** - 避免过度收集用户信息的嫌疑
2. **中性表述** - "账号"比"手机号"更中性
3. **用户友好** - 不让用户感觉被强制提供手机号

### 避免审核风险
1. **不明确说明账号类型** - 只说"账号"，不说"手机号"
2. **保持功能一致** - 实际功能不变，只是文案优化
3. **符合行业惯例** - 大多数应用都使用"账号"表述

## 注意事项

### 1. 保持一致性
- 所有用户可见的文案都使用"账号"
- 内部代码可以保持原有命名
- 日志输出也建议使用"账号"

### 2. 避免混用
- 不要在同一个界面混用"账号"和"手机号"
- 保持文案的统一性
- 提升专业度

### 3. 未来扩展
- 如果未来支持其他类型的账号（如邮箱）
- 文案不需要修改
- 只需要调整验证逻辑

### 4. 用户理解
- "账号"是通用概念，用户容易理解
- 配合 +86 前缀，用户知道输入手机号
- 不需要额外说明
