# 日期选择器修复说明

## 修复的问题

### 1. 编辑时日期不会跳转到已填写的日期
**问题原因**：
- AcceptanceDialog 在编辑模式下使用的是 `record.createTime` 而不是 `record.acceptanceTime`
- 没有正确处理日期解析和验证

**修复方案**：
- 优先使用 `record.acceptanceTime`，其次使用 `record.createTime`
- 添加日期有效性检查，防止无效日期导致的错误
- 确保日期选择器的年月日值正确初始化

### 2. 新增时选择日期点击确定日期没有变化
**问题原因**：
- `picker-view` 的 `value` 属性索引计算可能出现负数或超出范围
- 没有对索引进行边界检查

**修复方案**：
- 在所有 `computed` 索引计算中添加边界检查
- 确保索引值始终在有效范围内（>= 0 且 < 数组长度）
- 添加默认值处理，防止 NaN 或负数索引

### 3. 日期拖拽到第一天出现NaN的情况
**问题原因**：
- 月份切换时没有正确处理天数边界
- `picker-view` 的 change 事件处理中缺少有效性验证

**修复方案**：
- 在所有日期变更事件中添加有效性检查
- 确保年、月、日的值都在合理范围内
- 当月份变更导致当前日期无效时，自动调整到该月的最后一天

### 4. 快速滑动时点击确定没有选中正确日期
**问题原因**：
- `picker-view` 组件的滚动惯性导致滚动过程中和最终停止位置不一致
- `change` 事件在滚动过程中就会触发，而不是等滚动完全停止
- 确定按钮点击时获取的是事件触发时的值，而不是最终停止位置的值

**修复方案**：
- 添加防抖机制，延迟 150ms 处理日期变更
- 确保在滚动停止后再更新选中的值
- 分别为检查日期和整改期限选择器添加独立的防抖定时器

### 5. 用户无法清楚看到当前选中的项
**问题原因**：
- 原生 `picker-view` 的选中项样式不够明显
- 用户在快速滑动时容易误以为没有选中任何项

**修复方案**：
- 通过动态计算当前选中项索引，为选中项添加特殊样式
- 选中项字体加大（30rpx → 36rpx）、加粗（font-weight: 600）
- 选中项颜色改为主题色（#AD9B4B）
- 添加淡色背景和圆角边框突出显示
- 添加平滑过渡动画（transition: all 0.2s ease）

## 修复后的效果

1. **编辑验收记录**：日期选择器会正确显示已保存的验收时间
2. **新增记录**：日期选择器操作流畅，不会出现选择无效的情况
3. **边界处理**：拖拽到月份边界时不会出现 NaN，会自动调整到有效日期
4. **快速滑动**：快速滑动后点击确定能正确获取最终停止位置的日期
5. **视觉反馈**：选中项有明显的视觉区别，字体更大、颜色突出、有背景高亮
6. **用户体验**：日期选择更加稳定可靠，避免了各种边界情况和时序问题

## 技术要点

### 防抖机制
```javascript
// 添加防抖定时器
const dateChangeTimer = ref(null)

// 防抖处理日期变更
const debounceDateChange = (callback) => {
  if (dateChangeTimer.value) {
    clearTimeout(dateChangeTimer.value)
  }
  dateChangeTimer.value = setTimeout(callback, 150) // 150ms 防抖延迟
}

// 在事件处理中使用防抖
const onYearChange = (e) => {
  debounceDateChange(() => {
    const newYear = years.value[e.detail.value[0]]
    if (newYear) {
      selectedYear.value = newYear
      // 处理边界情况...
    }
  })
}
```

### 索引计算优化
```javascript
// 修复前
const dayIndex = computed(() => selectedDay.value - 1)

// 修复后
const dayIndex = computed(() => {
  const index = selectedDay.value - 1
  const maxDays = new Date(selectedYear.value, selectedMonth.value, 0).getDate()
  return index >= 0 && index < maxDays ? index : 0
})
```

### 日期变更处理优化
```javascript
// 修复前：立即处理
const onMonthChange = (e) => {
  selectedMonth.value = e.detail.value[0] + 1
  // ...
}

// 修复后：防抖处理
const onMonthChange = (e) => {
  debounceDateChange(() => {
    const newMonth = e.detail.value[0] + 1
    if (newMonth >= 1 && newMonth <= 12) {
      selectedMonth.value = newMonth
      // 处理边界情况...
    }
  })
}
```

### 编辑时日期初始化优化
```javascript
// 修复前：只使用 createTime
if (record.createTime) {
  const date = new Date(record.createTime)
  // ...
}

// 修复后：优先使用 acceptanceTime
let dateToUse = null
if (record.acceptanceTime) {
  dateToUse = new Date(record.acceptanceTime)
} else if (record.createTime) {
  dateToUse = new Date(record.createTime)
} else {
  dateToUse = new Date()
}

// 确保日期有效
if (isNaN(dateToUse.getTime())) {
  dateToUse = new Date()
}
```

## 防抖延迟说明

选择 150ms 作为防抖延迟的原因：
- **太短（< 100ms）**：可能无法完全等待滚动停止
- **太长（> 300ms）**：用户体验不佳，感觉响应迟钝
- **150ms**：平衡了响应速度和准确性，既能等待滚动停止，又不会让用户感觉卡顿

这些修复确保了日期选择器在各种操作场景下都能正常工作，特别是解决了快速滑动时的时序问题，提供了更好的用户体验。
