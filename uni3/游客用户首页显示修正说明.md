# 游客用户首页显示修正说明

## 问题分析

根据日志显示，游客登录成功后出现了首页显示问题：
- `用户类型: guest`
- `未知用户类型: guest` - 游客用户被当作未知类型处理
- 游客用户应该按照客户页面显示，但被归类为"未知用户类型"

## 修正内容

### 1. 修正页面显示逻辑

#### 修正前的问题
```vue
<!-- 客户视图（已登录的客户） -->
<CustomerDashboard v-else-if="userType === 'customer'" />

<!-- 员工视图（已登录的员工） -->
<StaffDashboard v-else-if="userType === 'staff'" />

<!-- 兜底状态（理论上不应该到达这里） -->
<view v-else class="empty-state">
  <text class="empty-text">页面加载中...</text>
</view>
```

游客用户（`userType === 'guest'`）不匹配任何条件，被归类为"未知用户类型"。

#### 修正后的逻辑
```vue
<!-- 客户视图（已登录的客户和游客用户） -->
<CustomerDashboard 
  v-else-if="userType === 'customer' || userType === 'guest'"
  :projects="projects"
  :current-project="currentProject"
  :loading="loading"
  @switch-project="handleSwitchProject"
  @navigate="navigateTo"
/>

<!-- 员工视图（已登录的员工） -->
<StaffDashboard 
  v-else-if="userType === 'staff'"
  :projects="staffProjects"
  :loading="loading"
  :selected-project-id="selectedStaffProjectId"
  :loading-more="loadingMore"
  :has-more="hasMore"
  @view-project="handleViewProject"
  @select-project="handleSelectStaffProject"
/>
```

### 2. 修正数据加载逻辑

#### 游客用户数据处理
```javascript
if (userType.value === 'customer' || userType.value === 'guest') {
  console.log('[Dashboard] 加载客户/游客首页数据...')
  
  // 游客用户不调用API，直接设置空数据
  if (userType.value === 'guest') {
    console.log('[Dashboard] 游客用户，设置空项目数据')
    projects.value = []
  } else {
    // 正式客户用户调用API获取数据
    const data = await getCustomerDashboard()
    console.log('[Dashboard] 客户数据:', data)
    projects.value = data?.projects || []
    // ... 其他逻辑
  }
}
```

### 3. 修正刷新和加载逻辑

#### 下拉刷新处理
```javascript
onPullDownRefresh(async () => {
  // 游客页面和游客用户的刷新处理
  if (shouldShowGuestView.value || userType.value === 'guest') {
    // 游客页面的刷新由CustomerDashboard组件内部处理
    // 游客用户不需要刷新项目数据
    uni.stopPullDownRefresh()
    return
  }
  
  await loadDashboardData(true)
  uni.stopPullDownRefresh()
})
```

#### 上拉加载处理
```javascript
onReachBottom(() => {
  // 游客页面和游客用户不需要加载更多用户数据
  if (shouldShowGuestView.value || userType.value === 'guest') {
    return
  }
  
  loadMoreData()
})
```

### 4. 修正底部占位逻辑

```javascript
<!-- 底部占位 (仅员工端需要，客户端和游客用户使用内部滚动) -->
<view class="tab-bar-placeholder" v-if="userType === 'staff'"></view>
```

## 修正后的用户类型处理

| 用户类型 | 显示页面 | 数据加载 | 刷新处理 | 底部占位 |
|---------|---------|---------|---------|---------|
| 未登录 | 游客页面 | 公共数据 | 组件内部 | 无 |
| 游客模式 | 游客页面 | 公共数据 | 组件内部 | 无 |
| guest | 客户页面 | 空项目数据 | 跳过刷新 | 无 |
| customer | 客户页面 | API数据 | 正常刷新 | 无 |
| staff | 员工页面 | API数据 | 正常刷新 | 有 |

## 游客用户体验流程

### 1. 游客登录成功后
- **首页显示**：客户页面布局（Banner + 空项目区域 + 资讯）
- **项目区域**：显示"登录后可查看您的项目进度"提示
- **功能可用**：Banner点击、资讯浏览等公共功能

### 2. 个人中心页面
- **按钮显示**：关于我们 + 退出登录 + 导入历史数据
- **功能可用**：所有按钮都可正常点击

### 3. 导入数据成功后
- **用户类型**：从 `guest` 变为 `customer` 或 `staff`
- **首页显示**：对应角色的完整功能页面
- **数据加载**：正常调用API获取用户数据

## 错误处理优化

### 防止API调用错误
- 游客用户不调用 `getCustomerDashboard()` API
- 避免因为无效token导致的API错误
- 保持页面稳定性

### 状态一致性
- 确保用户类型与页面显示逻辑一致
- 避免出现"未知用户类型"的情况
- 提供合理的兜底处理
