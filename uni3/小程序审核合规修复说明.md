# 小程序审核合规修复说明

## 审核问题

**审核反馈**：小程序打开一进入页面，未浏览体验功能服务，即要求授权手机号码、头像、昵称进行授权登录，请在用户体验浏览功能服务后，再自行选择授权登录。

## 问题分析

1. **首页设置问题**：`pages.json` 中第一个页面是登录页面，用户启动后直接进入登录页
2. **强制登录拦截**：路由拦截器检查登录状态，未登录用户被强制跳转到登录页
3. **缺少体验入口**：用户没有机会先体验功能就被要求登录

## 修复方案

### 1. 修改首页设置
**文件**：`uni3/src/pages.json`

将首页从登录页改为功能页面（dashboard），让用户先进入功能页面体验：

```json
"pages": [
  {
    "path": "pages/dashboard/index",  // 改为首页
    "style": {
      "navigationBarTitleText": "项目概况",
      "navigationStyle": "custom",
      "enablePullDownRefresh": true,
      "backgroundTextStyle": "dark"
    }
  },
  {
    "path": "pages/login/index-new",  // 登录页移到后面
    "style": {
      "navigationBarTitleText": "登录",
      "navigationStyle": "custom"
    }
  }
]
```

### 2. 移除强制登录拦截
**文件**：`uni3/src/main.js`

修改路由拦截器，允许用户自由浏览所有功能页面：

- 将所有主要功能页面加入白名单
- 移除登录状态检查
- 只保留员工专属功能的权限检查

### 3. 优化游客模式自动设置
**文件**：`uni3/src/store/user.js`

修改用户状态初始化逻辑，首次进入时自动设置为游客模式：

```javascript
const initFromStorage = () => {
  // ... 恢复用户数据 ...
  
  // 如果没有任何登录信息且不是主动退出，自动进入游客模式
  const hasLoginInfo = token.value || userType.value
  const manualLogout = uni.getStorageSync('manualLogout')
  
  if (!hasLoginInfo && !manualLogout) {
    // 首次进入或清除数据后，自动设置为游客模式
    uni.setStorageSync('guestMode', true)
    console.log('[UserStore] 自动进入游客模式')
  }
}
```

### 4. 完善登录和登出逻辑
**登录成功时**：
- 清除游客模式标记
- 清除主动退出标记

**登出时**：
- 设置主动退出标记
- 清除游客模式标记

### 5. 添加明显的登录入口
**文件**：`uni3/src/pages/profile/index.vue`

在个人中心页面添加明显的登录按钮：
- **游客模式下**：显示"登录"按钮和"导入历史数据"按钮
- **正式登录后**：只显示"退出登录"按钮
- 按钮互斥显示，避免混淆

```javascript
// 按钮显示逻辑
<!-- 游客模式显示的按钮 -->
<template v-if="isGuestMode">
  <!-- 登录按钮 -->
  <view class="action-btn login-btn" @click="handleLogin">
    <text>登录</text>
  </view>
  
  <!-- 导入历史数据按钮 -->
  <view class="action-btn import-data-btn" @click="handleImportData">
    <text>导入历史数据</text>
  </view>
</template>

<!-- 正式用户显示的按钮 -->
<template v-else>
  <!-- 退出登录按钮 -->
  <view class="action-btn logout-btn" @click="handleLogout">
    <text>退出登录</text>
  </view>
</template>

// 登录
const handleLogin = () => {
  uni.navigateTo({
    url: '/pages/login/index-new'
  })
}

// 退出登录（只处理正式用户）
const handleLogout = () => {
  uni.showModal({
    title: '提示',
    content: '确定要退出登录吗？',
    success: (res) => {
      if (res.confirm) {
        userStore.logout()
      }
    }
  })
}
```

## 修复后的用户流程

### 首次进入流程
1. **用户打开小程序** → 直接进入项目概况页面（dashboard）
2. **自动进入游客模式** → 可以浏览所有功能，看到示例数据
3. **用户体验功能** → 可以切换Tab、查看各个页面
4. **需要完整功能时** → 在个人中心看到"导入历史数据"按钮
5. **用户主动选择** → 点击按钮进入登录页面授权

### 游客模式体验
- ✅ 可以访问所有Tab页面
- ✅ 可以看到Banner和资讯
- ✅ 可以看到示例项目数据
- ✅ 可以体验界面和交互
- ✅ 在需要真实数据的地方显示友好提示

### 登录引导
- 🎯 在个人中心显示明显的"登录"按钮
- 🎯 保留"导入历史数据"按钮用于已有账号绑定
- 🎯 在需要真实数据的功能中显示提示
- 🎯 用户主动选择是否登录
- 🎯 不强制要求授权

## 合规要点

1. **先体验后授权**：用户可以先浏览功能，再选择是否登录
2. **主动选择**：登录是用户主动选择，不是强制要求
3. **功能可用**：游客模式下所有功能都可以体验
4. **友好引导**：通过"导入历史数据"等友好文案引导登录

## 按钮逻辑优化

### 按钮显示规则

**游客模式下显示**：
1. **关于我们** - 查看品牌介绍
2. **登录** - 直接跳转到登录页面（蓝色按钮，带用户图标）
3. **导入历史数据** - 用于已有账号的用户绑定微信（绿色按钮，带闪烁图标）

**正式登录后显示**：
1. **关于我们** - 查看品牌介绍  
2. **退出登录** - 退出当前账号（红色按钮）

### 按钮互斥逻辑

- 游客模式和正式登录状态的按钮完全互斥
- 避免同时显示"登录"和"退出登录"按钮造成混淆
- 通过 `v-if="isGuestMode"` 和 `v-else` 确保按钮正确显示

### 用户体验

- **清晰的状态区分**：用户一眼就能看出当前是游客模式还是已登录状态
- **明确的操作引导**：游客模式提供两种登录方式，已登录用户只需要退出功能
- **避免混淆**：不会出现多个相似功能的按钮同时存在
